# 漫流实时标题接收（1102）

以已验收的多参考图独立版本为基础，新增本地 SQLite inbox 接收。发送端采用既有 comic_article_inbox 协议；接收端在 Tk 主线程事务入库并更新同一标题列表，成功后回执 actual target_key。后台仅做探测和实例心跳，不操作 Tk。

标题库当前显示时局部刷新表格和剩余分类数量，保留搜索条件与筛选，并定位符合当前筛选的新标题；其他页面不跳转、不重建。整体保存之前合并离线投递回执，避免旧缓存删除新标题。

精确重复按去两端空白的标题、正文、分类三元组复用当前记录，保持消耗/停用状态；UUID冲突另分配新ID；单条格式错误留下失败回执并继续后续条目；事务失败撤回内存更新。已删除标题不从历史成功回执复活。多窗口共享同一数据库时暂缓在线接收。

兼容 comic_bridge_runtime(pid, db_path, version, heartbeat, phase)，版本标记 verified_push_bridge_v3_multi_reference，心跳反映实际数据根和 idle/busy。原漫流发送端的入库核对、最多3次重试及历史快照补发继续负责发送侧，无需替换其代码。

源码只修改4个UI/保存方法并新增刷新回调，原所有生图函数、上传函数及7个受保护模块（含多参考图）保持相同。40项隔离回归及真实发送端代码的临时数据库联调通过，不调用生文/生图模型。

统一维护约定见根目录AGENTS.md；其他窗口只交接需求，不发布生图程序。发布到新的目录并核对包内模块，保持活动数据库路径。217个多参考图账号、500个总账号和4844条标题在恢复后保留；不回滚作品。

# 参考图批量生图工作台

这是一个 Windows 桌面 GUI 工具，用 SQLite 维护参考图、画风、公众号、标题库和提示词，并按账号配置的生图方式（参考图生图 / 画风生图 / 六宫格参考图生图 / 参考图连续生图 / 六宫格画风生图）编排作品生产流程。

## 文件

- `picfactory_gui.py`：桌面 GUI、SQLite 数据访问、批量任务和账号生图编排
- `launch_gui.py` / `launch_gui.cmd`：源码启动入口
- `PicFactoryGUI.spec`：PyInstaller 打包配置
- `picfactory_matrix.db`：主数据库，管理数据和生成作品记录均保存在这里
- `data/`：矩阵库静态数据
- `assets/continuous_style_icon.ico`：桌面程序图标
- `image_clarity.py`、`batch_v10_01_text.py`、`naturalize_jfif_small_sharp_v10.py`：内置去AI处理模块
- `backups/`：历史数据库和状态备份，不参与运行
- `dist_latest/`、`build_latest/`：最近一次桌面版构建产物

## Python GUI

后期作为工具维护系统使用时，运行：

```bat
launch_gui.cmd
```

或：

```bat
python launch_gui.py
```

GUI 使用 Python 标准库 `tkinter`，批量任务额外使用 `httpx`、`openpyxl` 和 `Pillow`。可直接运行已打包的 `dist_latest\PicFactoryGUI\PicFactoryGUI.exe`。

当前数据存储采用 SQLite 主库 `picfactory_matrix.db`：矩阵维度、矩阵选项、角色绑定、固定风格模板、固定角色模板、构建模板、角色列表、文章提示词和分镜 Prompt 规则均从 SQLite 加载并保存。`picfactory_state.json` 只保留轻量界面配置和兼容迁移信息；启动时会自动从数据库恢复模板数据。批量任务的输入、生成状态和结果仍写回用户选择的 Excel，因为这些文件是批量处理的业务数据源。

GUI 当前保留批量写稿、批量生文、批量插图、批量生图、去AI、参考图管理、画风管理、账号管理和标题库。账号生图按账号选择一种生图方式：“参考图生图”按绑定参考图走文章、分镜和逐张生图；“画风生图”按画风提示词生图；“六宫格参考图生图”把正文直接画成一张四宫格或六宫格；“参考图连续生图”和画风生图一样按文章、分镜连续出多张，参考图是单幅，每一张都上传同一张参考图以保持画风和文案连续。角色维护、人设台、角色构建、风格构建、角色默认构建、图片切割和旧维护入口已移除。

### 图片精修

左侧导航“图片精修”维护“图片精修=是”账号的默认精修方案（处理管线来自 ImageRefineFactory，已内置为 `image_refine` 模块）：

- 参数与桌面版一致：画布比例 / 背景虚化 / 构图放大与裁切基准 / 导出质量 / 边框 / 圆角 / 阴影 / 光影色彩（亮度、对比度、饱和度、暖色）/ 质感（颗粒、锐度），另有可选的“全局信息图层”（透明图，拉伸铺满叠加在最上层）。
- 内置预设（清透 / 纸感 / 杂志 / 运营贴图）一键载入表单；默认方案为不改画幅的轻精修（锐度 5、颗粒 4）。
- 「保存默认精修配置」写入状态并立即生效；账号生图对“图片精修=是”的账号在去AI、切图之后按此方案就地精修成图，处理结果记入作品记录与运行日志。
- 精修可能改变画幅（画布比例≠原图时），宫格原图不做精修以保证等分切割。

### 参考图管理

“参考图管理”供“参考图生图”“六宫格参考图生图”和“参考图连续生图”使用；“画风生图”和“六宫格画风生图”使用“画风管理”：

- 支持“添加参考图”（多选文件）和“导入文件夹”（文件夹名自动作为分类）；图片会复制到项目根目录的 `reference_images/` 下，记录保存在 SQLite 的 `reference_images` 集合中，原始文件可随意移动或删除。
- 每张参考图可维护名称、分类、参考说明、启用状态和备注；右侧可预览缩略图，双击列表行用系统看图工具打开原图，支持“替换图片”“打开文件位置”和“删除”（删除会清空相关账号的绑定并删除项目内副本）。
- “参考说明”用文字概括画风、线条、配色和人物造型，生成分镜时写入提示词；参考图文件本身会随每一张图片请求一起上传。

### 参考图连续生图

账号的生图方式选“参考图连续生图”，并绑定一张单幅参考图。正文原句按顺序切开，分到每一张图，拼回去仍是原文。第 1 张只上传参考图。从第 2 张起，同一次请求先上传这张参考图，再上传上一张成图：参考图锁定线条、配色和人物画法，上一张成图承接人物、服装和场景。宫格为单幅时，每个画面一张图。请求尺寸跟随参考图像素。

### 六宫格画风生图

在“账号管理”中选择生图方式“六宫格画风生图”，并选择“画风管理”中启用且详情非空的画风。该方式是独立流程，不调用文章、留言或分镜模型，也不需要文章提示词、分镜规则和文本 API Key。读取标题库正文（正文为空时沿用原标题补齐规则），严格按下列格式组成生图 Prompt，不追加其他提示词：

```text
${画风详情}
画面段子内容：
${正文}
```

画风详情优先读取完整画风提示词 `full_prompt`，缺省时读取 `content`；画风详情本身应包含六宫格版式要求。每个标题正常只发起一次图片生成请求，不上传参考图，生成一张 `1024x1536` 的 2 列 × 3 行六宫格整图，再使用现有切图方案自动输出 `1.jpg` 至 `6.jpg`，切图成功后删除整图。该方式固定六宫格且自动切图，不受账号“宫格”和“是否切图”设置影响；保存账号时这两个字段自动补齐。去AI和图片精修继续按账号配置执行。图片请求失败沿用配置的重试策略，切图失败会记录为失败。

原“13生图”现显示为“六宫格参考图生图”，旧账号配置会自动兼容并在保存时更新名称，原有三段式参考图提示词及四宫格/六宫格、可选切图行为保持兼容。

### 账号生图

“账号生图”是面向最终作品的完整编排入口：

1. 选择启用的公众号。账号的标题分类、文章提示词、生图方式、参考图/画风、“人物特征（账号人设）”和“是否去AI”来自“账号管理”。“生图方式”为“参考图生图”的账号必须绑定一张启用且文件存在的参考图，为“画风生图”的账号必须选择一个在画风管理中存在且详情非空的画风，否则开始前直接报错。旧账号没有该字段时按“有参考图则参考图生图，否则有画风则画风生图”自动补齐。人物特征填写账号长期稳定的外貌、发型、五官、体型、服装、配饰和固定颜色；填写后作为唯一人物身份来源，参考图或画风只负责画风与人物造型气质。账号还有“宫格”（单幅 / 四宫格 / 六宫格）与“是否切图”两个字段：单幅=每个画面一张图；四宫格/六宫格=整个作品画成一张宫格图（2×2 或 2 列×3 行、无边框线，文章节点会被要求恰好产出 4/6 个画面，数量不符则整组重试），仅对搞笑漫画模板生效，其他模板按单幅处理并记日志；勾选“是否切图”后，宫格图用内置的 `image_splitter`（来自 PicFactory_ImageSplitter）按行列等分并裁掉 8px 边缘，切成 `1.jpg…N.jpg`，宫格原图保留为 `宫格.jpg`。宫格图不做 80px 留白后处理（会破坏等分切割），只做尺寸规范。 “图片精修”=是 时，成图（含切图单格）会再按“图片精修”工作区保存的默认方案自动精修（默认轻锐化+轻颗粒、不改画幅），宫格原图不精修；精修在去AI、切图之后执行，失败保留原图并记录。
2. 从“标题库”随机抽取该分类下的启用标题；标题数填 `0` 表示取完，否则按数量抽取。完整作品成功后，标题会自动标记为“停用”，并记录使用时间；失败或停止的标题不会停用，可在下次运行时重试。
3. 调用“文章提示词”生成文章。创作依据是标题库该条的“正文”：正文为空时，程序先把标题填入正文并写回标题库，再以正文执行；提示词里同时给出【输入标题】与【输入正文】，要求故事以正文为准。作品中的文章文件使用当前标题命名（例如 `论我家狗狗最喜欢吃的5种食物.txt`），内容为总标题、按标题实际结构解析出的编号主题和“评论区聊聊你家也这样吗？”，不带“主题：”和“画面：”外框。图片数量由文章决定：总标题 1 张封面，每个编号主题 1 张，不再使用前台手动分镜数。
   分镜环节按文章模板分两种情况：**搞笑漫画模板**的文章本身就是“画面N：…”连续画面结构，程序直接把每条结构清洗后作为对应分镜的画面内容，不再调用分镜模型；**其他模板**才调用“分镜 Prompt 规则”让文本模型拆分镜。两种情况下分镜画面都只描述与标题相关的内容（地点、人物动作表情、道具、构图、光线、对白），不含任何画风要求——画风只在生图阶段由图片 prompt 的专用模块携带（画风生图：【画风详情】；参考图生图：【参考图】+ 随请求上传的参考图），避免两处重复或冲突。
   分镜规则支持 `${画风}`/`${参考图}`/`${参考图说明}`、`${画风名称}`/`${参考图名称}`、`${人物}`、`${人物方案}`、`${文章}`、`${标题}` 和 `${分镜数量}` 占位符；其中画风/参考图占位符不再注入真实画风文本，而是替换为“画风不在分镜中描述”的惰性说明，名称占位符替换为绑定名称，因此同一条分镜规则可同时服务两种账号。文本结果按“场景画面N / 分镜N / 镜头N / 画面N”或编号格式解析为独立图片 Prompt，数量必须与文章解析结果一致。
4. 同一标题的图片 Prompt 按分镜顺序连续调用 gpt-image-2：“参考图生图”账号每次请求以 multipart 形式把参考图作为 `image` 字段上传到 `/images/edits`（默认由 `/images/generations` 地址推导，也可在 API 配置里用 `image_edit_endpoint` 显式指定）；“画风生图”账号保持原有 JSON 请求走 `/images/generations`，画风详情写在提示词中。参考图生图的**请求尺寸由参考图灵活决定**（请求尺寸 = 参考图实际像素，例如 1024×1024 的参考图就请求 `1024x1024`；生成配置里的“图片尺寸”只对画风生图生效），图片 prompt 中的【参考图】块是一份强制约束清单：生成尺寸与参考图一致、主体内容距画布四边至少 80 像素、色系只能取自参考图、人物脸型/头身比/服装表现沿用参考图造型、线条笔触画法沿用参考图、版式布局与装饰元素按“参考图里有什么就有什么、没有的不得发明”1:1 沿用参考图（条款不写死任何具体版式，换参考图自动适配）；参考图只决定这些，场景动作对白以分镜为准。**成图后处理**：网关返回的尺寸会波动、模型也不可靠地遵守留白要求，所以参考图生图的每张成图保存后由程序先同比例缩放到请求尺寸，再检测主体内容边界，任一边留白不足 80px 时整体缩放居中并用边缘背景色补边（`normalize_generated_image`），处理记录写入运行日志。**顶部小标题**：搞笑漫画模板的文章节点按“画面N：小标题｜画面结构”输出，小标题为 4–10 字，两种生图方式都会绘制：参考图生图完全参照参考图（参考图带标题区才按参考图排版绘制，没有标题区则不画）；画风生图画在画面顶部标题区（居中、字号大于对白，样式跟随画风详情）。**对白显式化**：文章节点把对白固定写成“角色名：“一句话””（内心独白写成“角色名（心想）：“一句话””），引号只用于要写进气泡的话；程序从每个画面结构中抽取这些对白（`extract_scene_dialogues`，排除“发病”这类被引号包住的非对白短语），在图片 prompt 里以【本张必须写进气泡的对白】正向列出并逐字进入白名单，硬约束“每条对白必须写进对应角色的气泡，禁止空气泡、禁止用图标替代文字，没有对白的角色不画气泡”；画面无对白时要求不画任何气泡。两种方式都复用同一个 HTTP 客户端、固定 Key 起点和可用的会话上下文，不同标题继续并发。
5. 文本阶段失败时，按“标题重试”次数重试文章、留言和分镜；生图阶段失败时，保留已成功的图片并续跑失败部分。重试次数耗尽后，失败原因和原标题、原正文会写入 SQLite。
6. 如果当前公众号账号的“是否去AI”为“是”，当前标题的全部图片生成成功后会自动调用内置 ImageClarityTool 进行两阶段清晰化处理；去AI现在按账号独立控制，与画风无关；处理失败不会把作品标记为成功。
7. 选择对应公众号，点击“重试失败任务”，可补跑已选账号仍未成功的历史失败标题，软件重启后同样可用。重试保留原账号、原标题和原正文，使用当前配置从文本阶段重新执行，不受“每账号标题数”限制；已成功或已使用的标题自动跳过，重复失败记录自动去重，结果更新回原作品记录。
8. 每批结束后，日志和页面会显示标题任务的成功、失败、停止、未执行数量，并逐账号列出结果。仅全部成功时显示“批量账号生图全部成功”；有失败时显示“批量账号生图结束（存在失败）”并弹出提醒，可通过“重试失败任务”继续处理。点击停止后，程序等待活动请求退出再给出最终统计。

账号生图直接使用配置的作品输出目录，不再新建 `YYYYMMDD_HHMMSS` 时间戳目录，作品保存到 `<输出目录>/<账号所属用户>/<公众号>/<标题>/`（默认输出目录为 `G:\作品`）；所属用户取自“账号管理”，为空时归入“未分配用户”目录，目录名称按现有文件名规则清理。真实作品目录只包含 `<标题>.txt` 和连续编号图片。分镜提示词、完整图片 Prompt、文案、路径、状态和错误信息保存在 SQLite 的 `generated_works` 集合中，不额外写入作品目录。

API 配置 JSON 支持两种格式：可分别提供 `text_api_keys`、`image_api_keys`，也可使用参考项目的 `api_keys` 数组并给每个 Key 标注 `types: ["text"]` 或 `types: ["image"]`。模型字段可用 `text_model`、`image_model`（图片默认 `gpt-image-2`），地址可用 `base_url` 或 `txt_url`/`image_url`；携带参考图的请求默认走 `image_endpoint` 推导出的 `/images/edits`，网关地址不规范时可用 `image_edit_endpoint` 单独指定。

### 连续标题生图

`批量生图` 会将 `_分镜` Sheet 按 `来源Sheet + Excel行号` 作为一个标题组。不同标题组按“标题并发数”并发；同一标题组内按 `画面序号` 串行调用，并复用同一个 HTTP 客户端和固定 API Key 起点，提示词会携带完整文案、上一张分镜和下一张分镜上下文。

标题组中任一张图片失败时，当前组生成的图片会被清理，随后从第 1 张开始重试。`标题重试次数` 默认 2 次；最终失败时该标题组的图片路径会清空、所有行统一标记为失败，下次运行会重新生成该标题的全部分镜，而不会只补失败行。

同一标题组始终复用同一个 HTTP 客户端和图片 Key 起点，组内严格串行。若图片网关支持会话参数，程序会自动把上一张响应 ID 作为下一张的 `previous_response_id`；不支持这些字段时会自动降级为固定客户端串行模式，并继续携带文章、前后分镜和画风详情上下文，不会把失败误判为标题任务成功。

## 用户操作手册：输入 Excel 字段名

### 固定角色 / 固定风格列表导入

在 `批量生文` 的 `固定角色 / 固定风格模板配置` 中，固定角色列表和固定风格列表都支持导入、导出 Excel。

导入 Excel 需要包含以下字段：

- `模板名称`
- `模板内容`

导入时会覆盖当前对应列表；导出时也会按这两列生成 Excel。

### 普通批量生文

普通 `批量生文` 会读取 Excel 每行字段内容，与写稿模板拼接后调用 GPT，并把结果写回输出列。

默认读取字段：

- `内容`
- `对话`

界面中的 `读取字段` 可以自行修改，多个字段用逗号分隔，例如：

```text
标题,内容,对话
```

如果 `读取字段` 留空，系统会读取 Excel 第一行中所有非系统字段。

留空读取全部字段时，会自动排除以下系统列：

- `写稿状态`
- `写稿错误`
- `写稿生成耗时`
- `生成状态`
- `错误信息`
- `角色构建`
- `风格构建`
- `固定风格`
- `风格构建模板`
- 当前输出列，默认是 `写稿结果`

写稿模板中可以使用 Excel 字段占位符，例如：

```text
${标题}
${内容}
${对话}
${全部字段}
${字段内容}
${角色构建}
${风格构建}
```

### 分镜批量生文

分镜批量生文会读取 Excel 中的对话和分镜文件名，定位 TXT 分镜提示词，调用 GPT 后写入 `_分镜` Sheet。

必填字段：

- `对话`
- `f分镜`

`f分镜` 列也兼容以下列名：

- `F分镜`
- `分镜名`
- `分镜`
- `分镜文件`
- `提示词文件`

可选字段：

- `文案`
- `固定风格`
- `风格构建模板`
